# 2. Understand Database Entities and Attributes

An entity represents something about which we need to store information.

An attribute represents a property of that entity.

For example:

### User Entity

| Attribute | Data Type | Description |
|---|---|---|
| id | BIGINT | Primary key |
| name | VARCHAR(100) | User name |
| email | VARCHAR(150) | Email address |
| password | VARCHAR(255) | Password hash |
| created_at | DATETIME | Creation timestamp |
| updated_at | DATETIME | Last update timestamp |

### Expense Entity

| Attribute | Data Type | Description |
|---|---|---|
| id | BIGINT | Primary key |
| user_id | BIGINT | Owner of expense |
| category_id | BIGINT | Expense category |
| amount | DECIMAL(12,2) | Expense amount |
| description | VARCHAR(255) | Expense description |
| expense_date | DATE | Date of expense |
| created_at | DATETIME | Creation timestamp |
| updated_at | DATETIME | Last update timestamp |

### Why Use DECIMAL for Money?

Suppose you store financial values using FLOAT.

Floating-point calculations can produce precision issues.

For example:

```javascript
console.log(0.1 + 0.2);
```

Output:

```text
0.30000000000000004
```

For financial records, use:

```sql
DECIMAL(12,2)
```

This stores decimal values with fixed precision.

**Important:** MySQL drivers commonly return DECIMAL values as strings to avoid losing precision. Avoid blindly converting financial values to JavaScript floating-point numbers for calculations. Use a decimal arithmetic library or perform appropriate calculations in SQL.

# 3. Understand Database Relationships

Our application will use three major relationship types.

## 3.1 One-to-Many Relationship

One user can have many expenses.

```text
USERS
  |
  | 1
  |
  |------------------|
                     |
                     | Many
                     |
                  EXPENSES
```

Example:

```text
User 1
   |
   |------ Expense 1
   |
   |------ Expense 2
   |
   |------ Expense 3
```

Database implementation:

```sql
CREATE TABLE expenses (

    id BIGINT PRIMARY KEY AUTO_INCREMENT,

    user_id BIGINT NOT NULL,

    amount DECIMAL(12,2) NOT NULL,

    FOREIGN KEY (user_id)
        REFERENCES users(id)

);
```

The `user_id` column acts as a foreign key.

## 3.2 One-to-Many: Category and Expenses

One category can be associated with multiple expenses.

```text
CATEGORY
   |
   | 1
   |
   |--------- Expense 1
   |
   |--------- Expense 2
   |
   |--------- Expense 3
```

## 3.3 One-to-Many: User and Categories

A user can create multiple custom categories.

```text
USER
  |
  | 1
  |
  |--------- Category 1
  |
  |--------- Category 2
  |
  |--------- Category 3
```

However, we also want globally available categories.

Therefore, our category table will contain:

```sql
user_id BIGINT NULL
```

Interpretation:

- `user_id = NULL`: Global category.
- `user_id = 10`: Category created by user 10.

This allows global and user-specific categories to coexist.

# 5. Understand the ER Diagram

An ER diagram represents database entities and their relationships.

Our database relationships:

```text
                  USERS
                    |
        |-----------|------------|
        |           |            |
        |           |            |
        v           v            v
     EXPENSES     INCOMES      BUDGETS
        |           |            |
        |           |            |
        v           v            v
              CATEGORIES
```

More precisely:

```text
USERS
  |
  |------< EXPENSES >------ CATEGORIES
  |
  |------< INCOMES >------- CATEGORIES
  |
  |------< BUDGETS >------- CATEGORIES
  |
  |------< CATEGORIES
```

Here:

- `1` represents one record.
- `<` represents many records.

### Important Design Consideration

A foreign key only verifies that the referenced record exists.

It does not automatically guarantee that the category belongs to the same user as the expense.

For example, a user could try to create an expense using another user's private category ID.

Therefore, our service layer must validate category ownership:

- The category must be global, or
- The category must belong to the authenticated user.
- The category type must be `expense` for an expense.
- The category type must be `income` for an income.

This is an important authorization and data-integrity rule.

# 6. Understand Sequelize Models

Before creating models, understand what a model is.

A Sequelize model represents a database table.

For example:

```text
User Model      → users table
Expense Model   → expenses table
Category Model  → categories table
```

A model defines:

- Table name.
- Columns.
- Data types.
- Constraints.
- Relationships.
- Model-level behavior.

### Basic Sequelize Model Example

```javascript
const { DataTypes } = require("sequelize");

const sequelize = require("../../database/connection");

const User = sequelize.define("User", {

    name: {

        type: DataTypes.STRING,

        allowNull: false

    },

    email: {

        type: DataTypes.STRING,

        allowNull: false,

        unique: true

    }

});

module.exports = User;
```

By default, Sequelize derives table names from model names and pluralizes them.

We will explicitly configure table names to avoid ambiguity.

# 7. Create the User Model

Create:

```text
src/database/models/User.js
```

Code:

```javascript
const { DataTypes } = require("sequelize");

const sequelize = require("../connection");

const User = sequelize.define(

    "User",

    {

        id: {

            type: DataTypes.BIGINT.UNSIGNED,

            primaryKey: true,

            autoIncrement: true

        },

        name: {

            type: DataTypes.STRING(100),

            allowNull: false

        },

        email: {

            type: DataTypes.STRING(150),

            allowNull: false,

            unique: true,

            validate: {

                isEmail: true

            }

        },

        password: {

            type: DataTypes.STRING(255),

            allowNull: false

        }

    },

    {

        tableName: "users",

        timestamps: true,

        underscored: true

    }

);

module.exports = User;
```

### Understanding Important Properties

**primaryKey:**

```javascript
primaryKey: true
```

Defines the primary key.

**autoIncrement:**

```javascript
autoIncrement: true
```

Automatically generates the next numeric ID.

**allowNull:**

```javascript
allowNull: false
```

Prevents NULL values.

**unique:**

```javascript
unique: true
```

Prevents duplicate email values at the database level.

**timestamps:**

```javascript
timestamps: true
```

Automatically manages:

- `createdAt`
- `updatedAt`

**underscored:**

```javascript
underscored: true
```

Uses snake_case database columns:

```text
created_at
updated_at
```

while keeping JavaScript model attributes in camelCase.

### Important

Sequelize validation and database constraints are different.

For example, `isEmail` is an application-level validation.

The database `UNIQUE` constraint protects against duplicate values at the database level.

Both are useful.

A user should not create duplicate budgets for the same:

- Month.
- Year.
- Category.

```text

```

does not prevent duplicate overall budgets.

We will handle this using an additional database-level strategy in the migration section.

# 12. Understand Sequelize Associations

Creating models is not enough.

We must define relationships between them.

Sequelize provides association methods.

| Association | Meaning |
|---|---|
| hasOne | One-to-one |
| belongsTo | Many-to-one |
| hasMany | One-to-many |
| belongsToMany | Many-to-many |

Our application mainly uses `hasMany` and `belongsTo`.

### User and Expenses

```javascript
User.hasMany(Expense);

Expense.belongsTo(User);
```

Meaning:

One user has many expenses.

Each expense belongs to one user.

### User and Categories

```javascript
User.hasMany(Category);

Category.belongsTo(User);
```

A user can have many custom categories.

Global categories have no user.

### Category and Expenses

```javascript
Category.hasMany(Expense);

Expense.belongsTo(Category);
```

One category can be used by many expenses.

```javascript
    as: "user"

});


// User - Category

User.hasMany(Category, {

    foreignKey: "userId",

    as: "categories"

});

Category.belongsTo(User, {

    foreignKey: "userId",

    as: "user"

});


// Category - Expense

Category.hasMany(Expense, {

    foreignKey: "categoryId",

    as: "expenses"

});

Expense.belongsTo(Category, {

    foreignKey: "categoryId",

    as: "category"

});


// User - Income

User.hasMany(Income, {

    foreignKey: "userId",

    as: "incomes"

});

Income.belongsTo(User, {

    foreignKey: "userId",

    as: "user"

});


// Category - Income

Category.hasMany(Income, {

    foreignKey: "categoryId",

    as: "incomes"

});

Income.belongsTo(Category, {

    foreignKey: "categoryId",

    as: "category"

});


// User - Budget

User.hasMany(Budget, {

    foreignKey: "userId",

    as: "budgets"

});

Budget.belongsTo(User, {

    foreignKey: "userId",

    as: "user"

});


// Category - Budget

Category.hasMany(Budget, {

    foreignKey: "categoryId",

    as: "budgets"

});

Budget.belongsTo(Category, {

    foreignKey: "categoryId",

    as: "category"

});


module.exports = {

    User,

    Category,

    Expense,

    Income,

    Budget

};
```

### Why Use aliases?

Example:

```javascript
User.hasMany(Expense, {

    as: "expenses"

});
```

Now we can use:

```javascript
const user = await User.findByPk(1, {

    include: "expenses"

});
```

Aliases make relationships explicit and help when a model participates in multiple associations.

### Important

The associations file must be loaded before running queries that use those associations.

# 15. Understand Sequelize Migrations

This is an important concept in professional backend development.

### What Is a Migration?

A migration is a version-controlled database schema change.

For example:

Initially:

```text
users
```

Later, you add:

```text
expenses
```

Then:

```text
categories
```

Each schema change can be represented by a migration file.

### Why Are Migrations Important?

Imagine you develop locally and create tables manually.

Your application works.

Now another developer clones your GitHub repository.

How will they create exactly the same database structure?

They need a repeatable process.

Migrations solve this problem.

### Migration History

```text
Migration 1:
    Create users table

Migration 2:
    Create categories table

Migration 3:
    Create expenses table

Migration 4:
    Create incomes table

Migration 5:
    Create budgets table
```

Migrations normally provide two operations:

**up():**

Applies a database change.

**down():**

Reverts that migration's change.

```javascript
"use strict";

module.exports = {

    async up(queryInterface, Sequelize) {

        await queryInterface.createTable("users", {

            id: {

                type: Sequelize.BIGINT.UNSIGNED,

                allowNull: false,

                autoIncrement: true,

                primaryKey: true

            },

            name: {

                type: Sequelize.STRING(100),

                allowNull: false

            },

                type: Sequelize.STRING(150),

                allowNull: false,

                unique: true

            },

            password: {

                type: Sequelize.STRING(255),

                allowNull: false

            },

            created_at: {

                type: Sequelize.DATE,

                allowNull: false,

                defaultValue: Sequelize.literal("CURRENT_TIMESTAMP")

            },

            updated_at: {

                type: Sequelize.DATE,

                allowNull: false,

                defaultValue: Sequelize.literal("CURRENT_TIMESTAMP")

            }

        });

    },

    async down(queryInterface) {

        await queryInterface.dropTable("users");

    }

};
```

### What Happens Here?

`createTable()` creates the database table.

`dropTable()` removes it.

The migration is reversible.

# 19. Create the Categories Migration

Run:

```bash
npx sequelize-cli migration:generate --name create-categories
```

Code:

```javascript
"use strict";

module.exports = {

    async up(queryInterface, Sequelize) {

        await queryInterface.createTable("categories", {

            id: {

                type: Sequelize.BIGINT.UNSIGNED,

                allowNull: false,

                autoIncrement: true,

                primaryKey: true

            },

            user_id: {

                type: Sequelize.BIGINT.UNSIGNED,

                allowNull: true,

                references: {

                    model: "users",

                    key: "id"

                },

                onUpdate: "CASCADE",

                onDelete: "CASCADE"

            },

            name: {

                type: Sequelize.STRING(100),

                allowNull: false

            },

            type: {

                type: Sequelize.ENUM("expense", "income"),

                allowNull: false

            },

            created_at: {

                type: Sequelize.DATE,

                allowNull: false,

                defaultValue: Sequelize.literal("CURRENT_TIMESTAMP")

            },

            updated_at: {
```

### Important: Preventing Duplicate Budgets

Our budget table allows `category_id` to be NULL.

In MySQL, a regular unique index permits multiple rows containing NULL in a unique key.

Therefore, simply creating:

```text
UNIQUE(user_id, category_id, month, year)
```

does not prevent duplicate overall budgets.

For this project, we will add generated columns in a follow-up migration to normalize NULL into a reserved value for uniqueness.

For example:

```sql
ALTER TABLE budgets
ADD COLUMN category_key BIGINT UNSIGNED
GENERATED ALWAYS AS (COALESCE(category_id, 0)) STORED;
```

Then:

```sql
CREATE UNIQUE INDEX unique_user_budget
ON budgets(user_id, category_key, month, year);
```

This allows only one overall budget per user per month and one budget per category per month.

The generated column is a database implementation detail and does not need to be exposed through the API.

# 26. Understand Database Indexes

An index helps the database find records efficiently.

Suppose a user has 100,000 expenses.

Your application frequently executes:

```sql
SELECT *
FROM expenses
WHERE user_id = 10;
```

Without a suitable index, MySQL may scan a large number of rows.

Create an index:

```sql
CREATE INDEX idx_expenses_user_id
ON expenses(user_id);
```

Now MySQL can use the index to locate matching records more efficiently.

### Composite Index

Suppose the application frequently executes:

```sql
SELECT *
FROM expenses
WHERE user_id = 10
AND expense_date BETWEEN '2026-11-01' AND '2026-11-30';
```

Create:

```sql
CREATE INDEX idx_expenses_user_date
ON expenses(user_id, expense_date);
```

### Why Composite Index?

It indexes multiple columns together.

The order matters.

An index on:

```text
(user_id, expense_date)
```

is generally useful for queries filtering by `user_id` alone and queries filtering by `user_id` followed by `expense_date`.

It is not equivalent to an index on:

```text
(expense_date, user_id)
```

### Important Indexing Rules

1. Index frequently queried columns.
2. Consider composite indexes for common multi-column filters.
3. Avoid unnecessary indexes.
4. Indexes consume storage.
5. Indexes add overhead to inserts, updates, and deletes.
6. Use `EXPLAIN` to inspect query plans.

Example:

```sql
EXPLAIN
SELECT *
FROM expenses
WHERE user_id = 10
AND expense_date = '2026-11-25';
```

We will cover query optimization in more detail later.

# 28. Understand Database Transactions

A transaction is a group of database operations that should succeed or fail together.

This is important for maintaining data integrity.

### Example

Suppose a user transfers ₹5,000 from one account to another.

We need to:

1. Deduct ₹5,000 from Account A.
2. Add ₹5,000 to Account B.

What happens if the first operation succeeds but the second fails?

Money becomes inconsistent.

Transactions solve this problem.

### ACID Properties

| Property | Meaning |
|---|---|
| Atomicity | All operations succeed or none do |
| Consistency | Data remains valid |
| Isolation | Concurrent transactions are controlled |
| Durability | Committed changes persist |

### Sequelize Transaction Example

```javascript
const sequelize = require("../database/connection");

const { Account } = require("../database/models");

async function transferMoney(fromId, toId, amount) {

    const transaction = await sequelize.transaction();

    try {

        const fromAccount = await Account.findByPk(fromId, {

            transaction,

            lock: transaction.LOCK.UPDATE

        });

        const toAccount = await Account.findByPk(toId, {

            transaction,

            lock: transaction.LOCK.UPDATE

        });

        if (!fromAccount || !toAccount) {

            throw new Error("Account not found");

        }

        if (Number(fromAccount.balance) < amount) {

            throw new Error("Insufficient balance");

        }

        await fromAccount.decrement("balance", {

            by: amount,

            transaction

        });

        await toAccount.increment("balance", {

            by: amount,

            transaction

        });

        await transaction.commit();

        return {

            success: true

        };

    } catch (error) {

        await transaction.rollback();

        throw error;

    }

}
```

This example is illustrative; an actual financial implementation should use precise decimal arithmetic and additional controls for concurrent transfers.

### What Is Commit?

```javascript
await transaction.commit();
```

Saves all changes.

### What Is Rollback?

```javascript
await transaction.rollback();
```

Reverts the uncommitted changes.

### Important

Every database operation that belongs to the transaction must receive the transaction object.

Otherwise, that operation may execute outside the transaction.

# 29. Automatic Transactions Using Managed Transactions

Sequelize also supports managed transactions.

Example:

```javascript
const result = await sequelize.transaction(async (transaction) => {

    const expense = await Expense.create(

        {

            userId: 1,

            categoryId: 2,

            amount: 500,

            description: "Food",

            expenseDate: "2026-11-25"

        },

            transaction

        }

    );

    return expense;

});
```

What happens?

- If the callback completes successfully, Sequelize commits.
- If the callback throws an error, Sequelize rolls back.

This is often cleaner than manually calling commit and rollback.

# 30. Understand Database Constraints

Constraints protect data integrity at the database level.

Common constraints:

| Constraint | Purpose |
|---|---|
| PRIMARY KEY | Uniquely identifies records |
| FOREIGN KEY | Maintains relationships |
| UNIQUE | Prevents duplicate values |
| NOT NULL | Prevents NULL values |
| CHECK | Validates allowed values |
| DEFAULT | Provides default values |

### Example: Amount Must Be Positive

```sql
ALTER TABLE expenses
ADD CONSTRAINT chk_expense_amount
CHECK (amount > 0);
```

### Example: Month Must Be Between 1 and 12

```sql
ALTER TABLE budgets
ADD CONSTRAINT chk_budget_month
CHECK (month BETWEEN 1 AND 12);
```

MySQL versions supporting enforced CHECK constraints will reject invalid values.

Always verify the database version and constraint behavior in your environment.

**Important:** Application validation and database constraints should complement each other.

Application validation provides friendly error messages.

Database constraints protect data integrity even when records are inserted outside your application.

# 31. Important Database Design Considerations

Before considering our database complete, understand these production-level decisions.

### 31.1 Soft Delete vs Hard Delete

Hard delete:

```sql
DELETE FROM expenses
WHERE id = 1;
```

The record is permanently removed.

Soft delete:

```text
deleted_at = current timestamp
```

The record remains in the database but is treated as deleted by the application.

Sequelize supports soft deletion through:

```javascript
paranoid: true
```

When using paranoid models, Sequelize automatically manages the `deletedAt` timestamp.

For this project, we will initially use hard deletion for simplicity. We can introduce soft deletion later if required.

### 31.2 Avoid Cascading Deletes for Important Financial Records

Our initial migration uses cascading deletion from user to expenses and incomes.

That is acceptable for a learning project, but production systems often need more careful retention and account-deletion policies.

For financial records, consider:

- Archiving.
- Soft deletion.
- Anonymization.
- Legal retention requirements.
- Explicit account-deletion workflows.

### 31.3 Validate Category Ownership

A user must not use another user's private category.

Example validation query:

```javascript
const category = await Category.findOne({

    where: {

        id: categoryId,

        type: "expense",

        [Op.or]: [

            { userId: userId },

            { userId: null }

        ]

    }

});
```

This allows either:

- A category owned by the authenticated user.
- A global category.

You must import `Op`:

```javascript
const { Op } = require("sequelize");
```

If the category is not found, reject the request.

### 31.4 Validate Budget Ownership

The same principle applies to category-specific budgets.

A user must not create a budget using another user's private category.

### 31.5 Avoid Using sync() for Production Schema Management

You may see:

```javascript
sequelize.sync();
```

This synchronizes models with database tables.

It can be useful for quick prototypes and isolated tests.

For production schema evolution, prefer migrations.

# 33. Common Errors and Troubleshooting

### Error 1: Foreign Key Constraint Is Incorrectly Formed

Possible causes:

- Parent table does not exist.
- Data types differ.
- Signed and unsigned integer types do not match.
- Storage engine does not support foreign keys.

Check that both columns use compatible types.

For example:

```text
users.id       BIGINT UNSIGNED
expenses.user_id BIGINT UNSIGNED
```

### Error 2: Cannot Add Foreign Key Constraint

Make sure the referenced table migration runs first.

Correct migration order:

```text
1. users
2. categories
3. expenses
4. incomes
5. budgets
```

### Error 3: Duplicate Entry for Unique Email

Possible reason:

An account already exists with the same email.

Check before creating the user and handle the database unique-constraint error.

### Error 4: SequelizeEagerLoadingError

Possible reason:

You used the wrong association alias.

For example, if the association is:

```javascript
Expense.belongsTo(Category, {
    as: "category"
});
```

Your query must use:

```javascript
include: [{
    model: Category,
    as: "category"
}]
```

### Error 5: Migration Already Executed

Sequelize CLI tracks migrations in `SequelizeMeta`.

If a migration has already executed, editing that migration file does not automatically apply the changes again.

Create a new migration for subsequent schema changes.

### Q13. What is the difference between hasMany and belongsTo?

`hasMany` defines the one-to-many side of a relationship. `belongsTo` defines the side that contains the foreign key.

### Q14. What is an index?

An index is a database structure that helps retrieve records efficiently.

### Q15. What is a composite index?

An index that contains multiple columns.

### Q16. What is a transaction?

A transaction groups database operations so they can be committed or rolled back together.

### Q17. What are ACID properties?

Atomicity, Consistency, Isolation, and Durability.

### Q18. What is the difference between commit and rollback?

Commit saves transaction changes. Rollback cancels uncommitted changes.

### Q19. Why should we use DECIMAL instead of FLOAT for money?

DECIMAL provides fixed-point precision, which is more appropriate for financial values.

### Q20. What is the difference between soft delete and hard delete?

Hard delete permanently removes a record. Soft delete marks a record as deleted while retaining it.

### Q21. What is eager loading in Sequelize?

Eager loading retrieves associated records using `include`.

### Q22. What is lazy loading?

Lazy loading retrieves associated records separately when they are needed.

### Q23. Why should we avoid sequelize.sync() in production?

Because migrations provide controlled, versioned, and reviewable database schema changes.

### Q24. What is referential integrity?

It ensures that relationships between database records remain valid.

### Q25. Does a foreign key guarantee that an expense category belongs to the same user?

No. It only verifies that the referenced category exists. Ownership must be enforced separately through application logic or stronger database constraints.
