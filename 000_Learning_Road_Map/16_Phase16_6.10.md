# 2. What Is File Uploading?

File uploading means transferring a file from a client application to a server or storage service.

For example, suppose a user selects:

```text
receipt.jpg
```

The browser sends the file to the backend.

The backend processes it and stores it somewhere.

The database generally stores information about the file, such as:

- Original filename.
- Stored filename.
- File path or storage key.
- MIME type.
- File size.
- Uploading user ID.
- Upload timestamp.

**Important:** Usually, we do not store the actual file binary data inside the database. We store the file in a storage system and keep its reference or metadata in the database.

# 3. Understanding multipart/form-data

Before implementing uploads, we need to understand how browsers send files.

You already know JSON requests.

Example:

```http
POST /api/users
Content-Type: application/json
```

```json
{
    "name": "John",
    "email": "john@example.com"
}
```

But JSON is not the standard format used by HTML forms for uploading files.

For file uploads, browsers commonly use:

```http
Content-Type: multipart/form-data
```

### What is multipart/form-data?

It is an HTTP request body format that allows multiple pieces of data to be sent together.

For example:

```text
name = John
email = john@example.com
profilePicture = profile.jpg
```

Each field is represented as a separate part of the request.

### HTML example

```html
<form
    action="/api/users/profile"
    method="POST"
    enctype="multipart/form-data"
>
    <input
        type="text"
        name="name"
    />

    <input
        type="file"
        name="profilePicture"
    />

    <button type="submit">
        Upload
    </button>
</form>
```

The important attribute is:

```html
enctype="multipart/form-data"
```

Without it, a traditional HTML form will not send the selected file in the required multipart format.

### JavaScript FormData example

You can also upload files using JavaScript.

```javascript
const formData = new FormData();

formData.append("name", "John");

formData.append("profilePicture", fileInput.files[0]);


await fetch("/api/users/profile", {

    method: "POST",

    body: formData

});
```

**Important:** Do not manually set the `Content-Type` header when using browser `FormData`.

The browser automatically generates the multipart boundary and includes it in the header.

# 4. Understanding Buffer in Node.js

Before learning Multer, we need to understand `Buffer`.

### What is a Buffer?

A Buffer is a Node.js object used to represent and work with raw binary data.

Files are stored as binary data.

For example:

- Images.
- Videos.
- PDFs.
- Audio files.
- ZIP archives.

Node.js uses Buffer to handle binary data.

### Example

```javascript
const buffer = Buffer.from("Hello World");

console.log(buffer);
```

Output will represent the string as bytes.

```text
<Buffer 48 65 6c 6c 6f 20 57 6f 72 6c 64>
```

Each hexadecimal value represents a byte.

### Buffer to String

```javascript
const buffer = Buffer.from("Hello World");

console.log(buffer.toString());
```

Output:

```text
Hello World
```

### Creating a Buffer from Binary Data

```javascript
const buffer = Buffer.from([65, 66, 67]);

console.log(buffer.toString());
```

Output:

```text
ABC
```

### Buffer properties

```javascript
const buffer = Buffer.from("Hello World");

console.log(buffer.length);

console.log(buffer.toString());

console.log(buffer.toJSON());
```

Important properties:

| Property | Description |
|---|---|
| `length` | Number of bytes |
| `toString()` | Converts bytes into text |
| `toJSON()` | Returns a JSON representation |
| `Buffer.from()` | Creates a Buffer |
| `Buffer.alloc()` | Creates an initialized Buffer |
| `Buffer.isBuffer()` | Checks whether a value is a Buffer |

### Why is Buffer important for file uploads?

When a file is uploaded using Multer's memory storage, its contents are available as a Buffer.

For example:

```javascript
req.file.buffer
```

This buffer can then be uploaded to Cloudinary, AWS S3, or another storage service.

# 5. Understanding Streams in Node.js

Another important concept is Streams.

### What is a Stream?

A stream is a mechanism for processing data piece by piece rather than loading the entire dataset into memory at once.

Consider a 2 GB video file.

If we load the entire file into memory:

```javascript
const fs = require("fs");

const data = fs.readFileSync("video.mp4");
```

The entire file is read into memory.

This can consume significant RAM.

Instead, we can use a stream.

```javascript
const fs = require("fs");

const readStream = fs.createReadStream("video.mp4");

readStream.on("data", (chunk) => {

    console.log("Received chunk:", chunk.length);

});

readStream.on("end", () => {

    console.log("File reading completed");

});
```

The file is processed in smaller chunks.

### Types of Streams

Node.js has four fundamental stream types.

| Stream | Description | Example |
|---|---|---|
| Readable | Reads data | `fs.createReadStream()` |
| Writable | Writes data | `fs.createWriteStream()` |
| Duplex | Reads and writes data | TCP socket |
| Transform | Modifies data while processing | Compression stream |

### Example: Copying a File Using Streams

```javascript
const fs = require("fs");

const readStream = fs.createReadStream("input.mp4");

const writeStream = fs.createWriteStream("output.mp4");


readStream.pipe(writeStream);


writeStream.on("finish", () => {

    console.log("File copied successfully");

});
```

### Buffer vs Stream

| Buffer | Stream |
|---|---|
| Represents binary data in memory | Processes data incrementally |
| May hold an entire file | Can process large files in chunks |
| Useful for smaller files and APIs requiring in-memory data | Useful for large files and continuous data |
| Can consume more memory for large files | Helps control memory usage |

**Important:** Streams are not automatically memory-free. They still use buffers internally, but they avoid loading the entire file into memory at once.

# 6. What Is Multer?

Now let's understand the main library we will use.

**Multer** is an Express middleware for handling `multipart/form-data`.

It is commonly used for file uploads.

Install it:

```bash
npm install multer
```

### Why do we need Multer?

Express's built-in JSON parser:

```javascript
app.use(express.json());
```

does not parse multipart file uploads.

Multer handles the multipart request and makes uploaded files available through the request object.

### How Multer works

```text
Client
  |
  v
multipart/form-data
  |
  v
Express Route
  |
  v
Multer Middleware
  |
  v
Parse File and Fields
  |
  v
req.file / req.files
  |
  v
Controller
```

# 7. Multer Storage Engines

Multer provides two commonly used storage engines.

1. Disk Storage.
2. Memory Storage.

## 7.1 Disk Storage

Disk storage saves uploaded files directly to the server's filesystem.

Example:

```javascript
const multer = require("multer");

const storage = multer.diskStorage({

    destination: function (req, file, cb) {

        cb(null, "uploads/");

    },

    filename: function (req, file, cb) {

        const uniqueName =
            Date.now() + "-" + Math.round(Math.random() * 1E9);

        cb(null, uniqueName + "-" + file.originalname);

    }

});


const upload = multer({

    storage

});
```

Now use it in an Express route:

```javascript
app.post(
    "/upload",
    upload.single("file"),
    (req, res) => {

        console.log(req.file);

        res.json({
            message: "File uploaded successfully"
        });

    }
);
```

### What is `upload.single()`?

It handles one uploaded file.

```javascript
upload.single("file")
```

The string `"file"` must match the field name sent by the client.

The uploaded file becomes available through:

```javascript
req.file
```

### Important `req.file` properties

| Property | Description |
|---|---|
| `fieldname` | Form field name |
| `originalname` | Original uploaded filename |
| `encoding` | Encoding information |
| `mimetype` | Client-provided MIME type |
| `destination` | Destination directory |
| `filename` | Stored filename |
| `path` | Stored file path |
| `size` | File size in bytes |

## 7.2 Memory Storage

Memory storage keeps the uploaded file in RAM as a Buffer.

Example:

```javascript
const multer = require("multer");

const storage = multer.memoryStorage();

const upload = multer({

    storage

});
```

Now:

```javascript
app.post(
    "/upload",
    upload.single("file"),
    (req, res) => {

        console.log(req.file.buffer);

        res.json({
            message: "File received"
        });

    }
);
```

The file data is available through:

```javascript
req.file.buffer
```

### Disk vs Memory Storage

| Disk Storage | Memory Storage |
|---|---|
| Saves files to local disk | Stores file contents in RAM |
| Provides `req.file.path` | Provides `req.file.buffer` |
| Useful for local file storage | Useful for uploading directly to cloud storage |
| Consumes disk space | Consumes RAM |
| Can handle large files with appropriate limits | Large files can create memory pressure |

**Recommendation:** Use memory storage for small files when uploading directly to a cloud storage service. Always enforce strict file-size limits.

For large files, prefer a streaming or direct-to-cloud upload approach.

Multer provides several upload methods.

## 8.1 single()

Uploads one file.

```javascript

```

Access:


## 8.2 array()

Uploads multiple files using the same field name.

```javascript

```

Here:

- `images` is the field name.
- `5` is the maximum number of files.

Access:

```javascript
req.files
```

Example:

```javascript
app.post(
    "/images",
    upload.array("images", 5),
    (req, res) => {

        console.log(req.files);

        res.json({
            message: "Images uploaded"
        });

    }
);
```

## 8.3 fields()

Uploads multiple files using different field names.

Example:

```javascript
upload.fields([

    {
        name: "profilePicture",
        maxCount: 1
    },

    {
        name: "documents",
        maxCount: 3
    }

]);
```

Access:

```javascript
req.files.profilePicture;

req.files.documents;
```

## 8.4 none()

Accepts text fields but rejects uploaded files.

```javascript
upload.none();
```

Useful when you specifically want to parse multipart form fields without accepting files.

## 8.5 any()

Accepts files from any field.

```javascript
upload.any();
```

Use this carefully.

It is generally better to specify expected file fields and limits explicitly.

### Summary

| Method | Purpose |
|---|---|
| `single()` | One file |
| `array()` | Multiple files under one field |
| `fields()` | Multiple named file fields |
| `none()` | Text fields only |
| `any()` | Files from any field |

# 9. File Validation and Security

File upload validation is extremely important.

Never trust a file just because the browser says it is an image or PDF.

A malicious user could upload:

```text
malicious.exe
```

and rename it:

```text
profile.jpg
```

Checking only the extension is insufficient.

We need multiple validation layers.

### Validation layers

1. File size.
2. File extension.
3. MIME type.
4. File signature or magic bytes.
5. Generated storage filename.
6. Authorization.
7. Storage access restrictions.

Let's implement these.

## 9.1 File Size Validation

Example:

```javascript
const upload = multer({

    storage: multer.memoryStorage(),

    limits: {

        fileSize: 5 * 1024 * 1024

    }

});
```

This allows a maximum file size of 5 MB per file.

Remember:

```text
1 KB = 1024 bytes
1 MB = 1024 × 1024 bytes
```

You can also limit the number of files.

```javascript
const upload = multer({

    storage: multer.memoryStorage(),

    limits: {

        fileSize: 5 * 1024 * 1024,

        files: 5

    }

});
```

## 9.2 MIME Type Validation

MIME types describe the media type of a file.

Examples:

| File | MIME Type |
|---|---|
| JPEG | `image/jpeg` |
| PNG | `image/png` |
| WebP | `image/webp` |
| PDF | `application/pdf` |
| MP4 | `video/mp4` |
| TXT | `text/plain` |

Multer provides a `fileFilter` option.

Example:

```javascript
const allowedTypes = [

    "image/jpeg",

    "image/png",

    "image/webp"

];


const upload = multer({

    storage: multer.memoryStorage(),

    fileFilter: (req, file, cb) => {

        if (allowedTypes.includes(file.mimetype)) {

            cb(null, true);

        } else {

            cb(new Error("Invalid file type"));

        }

    }

});
```

**Important:** `file.mimetype` comes from the incoming multipart request. It is user-controlled metadata and can be spoofed.

For stronger validation, inspect the actual file signature.

# 10. Understanding File Signatures (Magic Bytes)

A file signature is a sequence of bytes that helps identify a file's actual format.

Examples:

| File Format | Signature |
|---|---|
| JPEG | `FF D8 FF` |
| PNG | `89 50 4E 47` |
| PDF | `25 50 44 46` |
| GIF | `47 49 46 38` |

Suppose someone uploads an executable file but names it:

```text
image.jpg
```

Its extension and declared MIME type may look valid.

But its file signature will not match JPEG.

### Using file-type package

Install:

```bash
npm install file-type
```

Recent versions of `file-type` are ESM-only. Since our project uses CommonJS, dynamically import it:

```javascript
const { fileTypeFromBuffer } = await import("file-type");
```

Example validation:

```javascript
async function validateImageFile(buffer) {

    const { fileTypeFromBuffer } = await import("file-type");

    const fileType = await fileTypeFromBuffer(buffer);

    const allowedTypes = [

        "image/jpeg",

        "image/png",

        "image/webp"

    ];


    if (!fileType || !allowedTypes.includes(fileType.mime)) {

        throw new Error("Invalid image content");

    }


    return fileType;

}
```

This checks the actual detected file format rather than trusting the filename or MIME type.

For production applications, image decoding and re-encoding can provide an additional security layer.

Also, file-signature validation alone does not guarantee that a file is harmless.

# 11. Creating a Reusable Upload Middleware

Instead of configuring Multer separately for every route, create a reusable middleware.

Project structure:

```text
src/
│
├── middlewares/
│   └── upload.middleware.js
│
├── modules/
│   ├── users/
│   └── expenses/
│
└── app.js
```

### upload.middleware.js

```javascript
const multer = require("multer");


const storage = multer.memoryStorage();


const imageTypes = [

    "image/jpeg",

    "image/png",

    "image/webp"

];


const upload = multer({

    storage,

    limits: {

        fileSize: 5 * 1024 * 1024,

        files: 5

    },

    fileFilter: (req, file, cb) => {

        if (!imageTypes.includes(file.mimetype)) {

            return cb(
                new Error("Only JPEG, PNG and WebP images are allowed")
            );

        }

        cb(null, true);

    }

});


module.exports = upload;
```

### Using it in routes

```javascript
const express = require("express");

const upload = require("../../middlewares/upload.middleware");

const router = express.Router();


router.post(

    "/profile-picture",

    upload.single("profilePicture"),

    (req, res) => {

        res.json({
            message: "File received successfully"
        });

    }

);


module.exports = router;
```

This is a starting point. We will add actual file-signature validation and cloud storage in the next sections.

# 12. File Storage Options

Now let's understand where uploaded files can be stored.

There are three common approaches.

## 12.1 Local Storage

Files are stored on the application's server.

Example:

```text
project/
│
├── uploads/
│   ├── profile/
│   ├── receipts/
│   └── documents/
```

Example:

```javascript
const fs = require("fs");

const path = require("path");


const uploadDirectory = path.join(
    process.cwd(),
    "uploads"
);


if (!fs.existsSync(uploadDirectory)) {

    fs.mkdirSync(uploadDirectory, {
        recursive: true
    });

}
```

### Advantages

- Easy to implement.
- No external storage service required.
- Useful for development.
- Simple local file access.

### Disadvantages

- Limited server storage.
- Backup and recovery responsibilities.
- Difficult scaling across multiple servers.
- Files can disappear when using temporary or ephemeral deployment storage.
- Requires additional work for secure public/private access.

**Important:** Local storage is not automatically persistent on every hosting platform. Verify the platform's filesystem and volume configuration before relying on it.

## 12.2 Cloudinary

Cloudinary is a cloud media management platform.

It provides:

- Image storage.
- Image transformations.
- Image optimization.
- Image delivery.
- Video management.
- CDN delivery.

Useful for:

- Profile pictures.
- Product images.
- Blog images.
- Expense receipt images.

Official website: [Cloudinary](https://cloudinary.com?utm_source=chatgpt.com)

## 12.3 AWS S3

Amazon S3 is an object storage service.

It is commonly used for:

- PDFs.
- Documents.
- Images.
- Videos.
- Backups.
- Large files.

Official documentation: [Amazon S3](https://aws.amazon.com/s3/?utm_source=chatgpt.com)

### Local vs Cloudinary vs S3

| Feature | Local Storage | Cloudinary | AWS S3 |
|---|---|---|---|
| Storage location | Application server | Cloud | Cloud |
| Image optimization | Manual | Built-in | Usually separate processing |
| CDN integration | Requires setup | Available | CloudFront integration |
| Document storage | Yes | Supported | Yes |
| Scalability | Limited by server | Cloud-based | Highly scalable |
| Best use | Development/small apps | Media-heavy apps | General object storage |

For our Expense Tracker:

- Cloudinary is convenient for profile pictures and receipt images.
- S3 is a strong option for receipts, invoices, and documents.
- Local storage is suitable for development.

# 13. Implementing Local File Storage

Let's implement a basic local upload service.

For this example, we will use Multer disk storage.

### upload.middleware.js

```javascript
const multer = require("multer");

const path = require("path");


const storage = multer.diskStorage({

    destination: (req, file, cb) => {

        const uploadPath = path.join(
            process.cwd(),
            "uploads"
        );

        cb(null, uploadPath);

    },


    filename: (req, file, cb) => {

        const extension = path.extname(file.originalname);

        const uniqueName =
            `${Date.now()}-${require("crypto").randomUUID()}${extension}`;

        cb(null, uniqueName);

    }

});


const upload = multer({

    storage,

    limits: {

        fileSize: 5 * 1024 * 1024

    }

});


module.exports = upload;
```

Notice that we are generating a unique filename instead of directly trusting the original filename.

However, this example still requires actual content validation before the file is accepted for production use.

### Controller

```javascript
const uploadFile = async (req, res) => {

    if (!req.file) {

        return res.status(400).json({

            message: "Please upload a file"

        });

    }


    res.status(200).json({

        message: "File uploaded successfully",

        file: {

            originalName: req.file.originalname,

            filename: req.file.filename,

            path: req.file.path,

            size: req.file.size

        }

    });

};


module.exports = {
    uploadFile
};
```

### Route

```javascript
const express = require("express");

const upload = require("./upload.middleware");

const controller = require("./upload.controller");


const router = express.Router();


router.post(

    "/",

    upload.single("file"),

    controller.uploadFile

);


module.exports = router;
```

# 14. Serving Uploaded Files

If files are stored locally, Express can serve them using static middleware.

Example:

```javascript
app.use(
    "/uploads",
    express.static("uploads")
);
```

If a file exists at:

```text
uploads/profile-123.jpg
```

It may be accessible through:

```text
http://localhost:5000/uploads/profile-123.jpg
```

### Important Security Warning

Do not expose private files through unrestricted static middleware.

For example, expense receipts may contain:

- Names.
- Addresses.
- Purchase information.
- Payment details.
- Other sensitive information.

For private files, use an authenticated download endpoint.

Example:

```javascript
router.get(
    "/expenses/:id/receipt",
    authenticate,
    expenseController.downloadReceipt
);
```

The controller should:

1. Find the expense belonging to the authenticated user.
2. Verify the user has permission to access it.
3. Resolve the stored file.
4. Return the file through an appropriate response.

Never trust a client-provided filesystem path.

# 15. Database Design for File Metadata

Now let's design a database table to store file information.

We should not normally store the complete binary file in a regular metadata table.

Instead, store the reference to the actual file.

### files table

| Column | Type | Description |
|---|---|---|
| id | BIGINT | Primary key |
| user_id | BIGINT | Uploading user |
| original_name | VARCHAR(255) | Original filename |
| stored_name | VARCHAR(255) | Generated filename |
| storage_provider | VARCHAR(50) | local, cloudinary, s3 |
| storage_key | VARCHAR(500) | Object key or storage path |
| mime_type | VARCHAR(100) | File MIME type |
| size | BIGINT | File size in bytes |
| created_at | DATETIME | Upload timestamp |

### Example record

```json
{
    "id": 1,
    "userId": 10,
    "originalName": "restaurant-bill.jpg",
    "storedName": "a82f-91bc.jpg",
    "storageProvider": "cloudinary",
    "storageKey": "receipts/a82f-91bc",
    "mimeType": "image/jpeg",
    "size": 245678
}
```

Notice:

We store the Cloudinary public ID or S3 object key rather than depending exclusively on a public URL.

This makes file management easier.

### Why store metadata?

Because later we may need to:

- Retrieve files.
- Delete files.
- Track uploads.
- Enforce ownership.
- Check file sizes.
- Change storage providers.
- Generate temporary download links.

```javascript
const sequelize = require("../../database/connection");


const File = sequelize.define("File", {

    },

        type: DataTypes.STRING(255),

        allowNull: false,

        field: "original_name"

    },


    storedName: {

        type: DataTypes.STRING(255),

        allowNull: true,

        field: "stored_name"

    },


    storageProvider: {

        type: DataTypes.STRING(50),

        allowNull: false,

        field: "storage_provider"

    },


    storageKey: {

        type: DataTypes.STRING(500),

        allowNull: false,

        field: "storage_key"

    },


    mimeType: {

        type: DataTypes.STRING(100),

        allowNull: false,

        field: "mime_type"

    },


    size: {

        type: DataTypes.BIGINT,

        allowNull: false

    }

}, {

    tableName: "files",

    timestamps: true,

    underscored: true

});


module.exports = File;
```

### Association

In your model index:

```javascript
User.hasMany(File, {
    foreignKey: "userId",
    as: "files"
});


File.belongsTo(User, {
    foreignKey: "userId",
    as: "user"
});
```

You should also create a database migration with a foreign key referencing `users.id`.

### Step 3: Upload File

```javascript
const {
    PutObjectCommand
} = require("@aws-sdk/client-s3");

const s3 = require("../../config/s3");


async function uploadToS3(file) {

    const key =
        `receipts/${Date.now()}-${require("crypto").randomUUID()}`;


    const command = new PutObjectCommand({

        Bucket: process.env.AWS_S3_BUCKET,

        Key: key,

        Body: file.buffer,

        ContentType: file.mimetype

    });


    await s3.send(command);


    return {

        key

    };

}


module.exports = {
    uploadToS3
};
```

Here:

- `Bucket` identifies the S3 bucket.
- `Key` identifies the object inside the bucket.
- `Body` contains the file data.
- `ContentType` describes the file format.

For this example, `file.buffer` is provided by Multer memory storage.

For large files, use streaming or multipart uploads rather than loading the complete file into memory.

### Step 4: Delete File

```javascript
const {
    DeleteObjectCommand
} = require("@aws-sdk/client-s3");


async function deleteFromS3(key) {

    const command = new DeleteObjectCommand({

        Bucket: process.env.AWS_S3_BUCKET,

        Key: key

    });


    return await s3.send(command);

}
```

# 19. What Are Presigned URLs?

Suppose a user wants to download an expense receipt stored in a private S3 bucket.

We do not want to make the entire bucket public.

Instead, we can generate a temporary URL that allows access to a specific object.

This is called a **presigned URL**.

### How it works

```text
Client
  |
  v
Request Download
  |
  v
Node.js Backend
  |
  v
Authenticate User
  |
  v
Check File Ownership
  |
  v
Generate Presigned URL
  |
  v
Return Temporary URL
  |
  v
Client Downloads from S3
```

Install:

```bash
npm install @aws-sdk/s3-request-presigner
```

### Example

```javascript
const {
    GetObjectCommand
} = require("@aws-sdk/client-s3");

const {
    getSignedUrl
} = require("@aws-sdk/s3-request-presigner");

const s3 = require("../../config/s3");


async function generateDownloadUrl(key) {

    const command = new GetObjectCommand({

        Bucket: process.env.AWS_S3_BUCKET,

        Key: key

    });


    const url = await getSignedUrl(

        s3,

        command,

        {
            expiresIn: 300
        }

    );


    return url;

}
```

Here:

```javascript
expiresIn: 300
```

means the URL is valid for approximately 5 minutes.

**Important:** A presigned URL is a bearer credential. Anyone who obtains it can use it while it remains valid, subject to its permissions.

Always authorize the user before generating the URL.

# 20. File Deletion

File deletion is another important operation.

Suppose a user replaces their profile picture.

We need to:

1. Upload the new image.
2. Save its new storage reference.
3. Delete the old image.
4. Maintain consistency if any step fails.

### Why is this complicated?

Database transactions cannot automatically roll back a Cloudinary or S3 deletion.

For example:

```text
Delete old file from Cloudinary
        |
        v
Database update fails
        |
        v
User record still references deleted file
```

This creates an inconsistency.

### Recommended approach

For many applications:

1. Upload the new file.
2. Update the database reference.
3. Delete the old file afterward.
4. If old-file deletion fails, log it and retry using a background job.

This approach prefers temporarily having an unused old file over leaving a database record pointing to a file that no longer exists.

For critical workflows, use an outbox or cleanup job.

# 21. Image Optimization

Uploading a 10 MB image for a small profile picture is usually unnecessary.

Image optimization helps reduce:

- Storage consumption.
- Bandwidth.
- Download time.
- Page load time.

### Common optimization techniques

| Technique | Description |
|---|---|
| Resize | Reduce image dimensions |
| Compression | Reduce file size |
| WebP conversion | Convert to an efficient image format |
| AVIF conversion | Use another modern image format |
| Thumbnail generation | Create smaller preview images |
| Responsive images | Deliver suitable image sizes |

### Example using Cloudinary

Cloudinary supports image transformations.

Example URL transformation:

```text
https://res.cloudinary.com/demo/image/upload/w_300,h_300,c_fill/sample.jpg
```

Here:

- `w_300`: Width 300 pixels.
- `h_300`: Height 300 pixels.
- `c_fill`: Crop to fill the requested dimensions.

In production, use the official SDK to construct transformations rather than manually concatenating untrusted URL values.

### Why is optimization important?

Suppose a user uploads a 5 MB profile picture.

After optimization:

```text
Original: 5 MB
Optimized: 150 KB
```

This reduces the amount of data transferred to the browser.

The actual reduction depends on the original image, dimensions, format, and quality settings.

# 22. File Upload Security Checklist

File uploads introduce security risks.

Let's understand the most important ones.

### 1. File Extension Validation

Do not trust the extension alone.

A `.jpg` filename does not prove the file is a JPEG image.

### 2. MIME Type Validation

Check the declared MIME type, but remember it can be spoofed.

### 3. Magic Byte Validation

Inspect the file signature.

### 4. File Size Restriction

Prevent users from uploading extremely large files.

### 5. Random Filenames

Do not use raw user-provided filenames as storage paths.

### 6. Authentication

Only authenticated users should upload private application files.

### 7. Authorization

Users should only access files they own or are authorized to access.

### 8. Private Storage

Do not expose private documents through public URLs.

### 9. Malware Scanning

For applications accepting arbitrary documents, consider antivirus scanning or a dedicated file-scanning workflow.

### 10. Storage Limits

Prevent abuse through per-user quotas, rate limits, and total storage limits.

### 11. Avoid Path Traversal

Never accept arbitrary filesystem paths from users.

For example:

```text
../../.env
```

A malicious path must never be allowed to access application files.

### 12. Safe File Serving

Use the correct response headers and avoid executing uploaded content.

For highly sensitive applications, serve files from a separate origin or controlled download service.

# 23. Error Handling for Multer

Multer can generate errors.

Examples:

- File too large.
- Too many files.
- Unexpected file field.
- Invalid upload configuration.

We should handle these errors centrally.

Example:

```javascript
const multer = require("multer");


app.use((err, req, res, next) => {

    if (err instanceof multer.MulterError) {

        if (err.code === "LIMIT_FILE_SIZE") {

            return res.status(400).json({

                message: "File size exceeds the allowed limit"

            });

        }


        if (err.code === "LIMIT_FILE_COUNT") {

            return res.status(400).json({

                message: "Too many files uploaded"

            });

        }


        if (err.code === "LIMIT_UNEXPECTED_FILE") {

            return res.status(400).json({

                message: "Unexpected file field"

            });

        }

    }


    next(err);

});
```

Place this logic inside your existing central error-handling middleware rather than registering a second error handler unnecessarily.

Also, validate file contents after Multer processes the request.

| Monitoring | Track upload failures and storage consumption |
| Credentials | Keep cloud credentials in secure configuration |

### One more important concept: Direct-to-Cloud Uploads

In our current architecture:

```text
Browser → Node.js → Cloud Storage
```

The file passes through the Node.js server.

For large files or applications with heavy upload traffic, we can use:

```text
Browser → Cloud Storage
```

The backend first generates a temporary upload authorization or presigned URL.

The browser uploads the file directly to cloud storage.

The backend then verifies the uploaded object and saves its metadata.

This reduces application server bandwidth and memory consumption.

We will use this approach when designing more scalable upload systems.

# 26. Interview Questions and Answers

### Q1. What is Multer?

Multer is Express middleware used to process multipart/form-data requests, particularly file uploads.

### Q2. What is multipart/form-data?

It is an HTTP request encoding format that allows text fields and files to be sent together.

### Q3. What is Buffer in Node.js?

Buffer is a Node.js object used to represent and manipulate binary data.

### Q4. What is a Stream?

A stream processes data incrementally rather than requiring the entire dataset to be loaded into memory.

### Q5. What are the four types of Node.js streams?

Readable, Writable, Duplex, and Transform.

### Q6. What is the difference between Buffer and Stream?

A Buffer represents binary data in memory, while a stream provides incremental data processing.

### Q7. What is the difference between Disk Storage and Memory Storage in Multer?

Disk storage writes uploaded files to the filesystem. Memory storage keeps file contents in RAM as a Buffer.

### Q8. What is `upload.single()`?

It is a Multer method that handles one uploaded file from a specified form field.

### Q9. What is `req.file`?

It contains information about a single uploaded file processed by Multer.

### Q10. What is `req.files`?

It contains information about multiple uploaded files.

### Q11. What is a MIME type?

A MIME type identifies the media type of a file, such as `image/jpeg` or `application/pdf`.

### Q12. Why is MIME type validation alone insufficient?

Because the client can send a fake MIME type. The actual file content should also be inspected.

### Q13. What are magic bytes?

Magic bytes are identifying byte sequences found in a file's content that help determine its actual format.

### Q14. Why should we generate random filenames?

To avoid filename collisions, reduce filename manipulation risks, and prevent users from controlling storage paths.

### Q15. Why should we store file metadata in a database?

To track ownership, storage references, file size, MIME type, and other information required to manage files.

### Q16. What is Cloudinary?

Cloudinary is a cloud platform for storing, transforming, optimizing, and delivering media files.

### Q17. What is AWS S3?

Amazon S3 is a scalable object storage service used to store files and other objects.

### Q18. What is a presigned URL?

A presigned URL provides temporary access to a specific object in a private S3 bucket.

### Q19. Why should private files not be publicly accessible?

Because they may contain confidential or sensitive user information.

### Q20. What is direct-to-cloud uploading?

It is an architecture in which the browser uploads files directly to cloud storage instead of sending the entire file through the application server.

### Q21. Why is file size validation important?

It prevents excessive memory usage, storage consumption, bandwidth usage, and certain denial-of-service scenarios.

### Q22. Can database transactions roll back Cloudinary or S3 operations?

No. A database transaction cannot automatically reverse an external storage operation. Applications need cleanup, retry, or compensation mechanisms.
