## 1. Introduction

In the previous parts, we implemented three major financial modules:

1. Expense Management.
2. Income Management.
3. Budget Management.

Now we will combine these modules to build a **Financial Dashboard and Analytics System**.

A dashboard provides users with a summarized view of their financial activities.

Instead of retrieving expenses and incomes separately and calculating everything on the frontend, we will create dedicated backend APIs that return calculated financial information.

### What will our dashboard display?

Suppose a user has the following financial records:

**Income**

| Source | Amount |
|---|---:|
| Salary | ₹50,000 |

Our dashboard should calculate:

| Metric | Amount |
|---|---:|

We will also provide:

### Why do we need a separate Dashboard Module?

Imagine our frontend needs to display:

- Total income.
- Total expenses.
- Net balance.
- Category-wise spending.
- Monthly trends.

Without a dashboard API, the frontend might need to call multiple endpoints:

```text
GET /expenses
GET /incomes
GET /budgets
```

Then it would need to calculate totals and summaries.

This creates unnecessary network requests and duplicates business calculations on the frontend.

Instead, we can create:

```http
GET /api/v1/dashboard/summary
```

The backend will perform the calculations and return the required information in one response.

**The frontend should primarily display financial calculations, not independently implement the business rules behind them.**

# 3. Understanding Financial Calculations

Before implementing the APIs, let's understand the formulas.

## 3.1 Total Income

The sum of all income records during a selected period.

```text
Total Income = SUM(All Income Amounts)
```

Example:

```text
Salary       = ₹50,000
Freelancing  = ₹15,000
Business     = ₹10,000

Total Income = ₹75,000
```

SQL:

```sql
SELECT SUM(amount)
FROM incomes
WHERE user_id = 10;
```

## 3.2 Total Expenses

The sum of all expense records during a selected period.

```text
Total Expenses = SUM(All Expense Amounts)
```

SQL:

```sql
SELECT SUM(amount)
FROM expenses
WHERE user_id = 10;
```

## 3.3 Net Balance

```text
Net Balance = Total Income - Total Expenses
```

Example:

```text
Income   = ₹75,000
Expenses = ₹15,000

Balance  = ₹60,000
```

## 3.4 Savings Rate

Savings rate represents the percentage of income remaining after expenses.

Formula:

```text
Savings Rate =
((Income - Expenses) / Income) × 100
```

Example:

```text
Income   = ₹75,000
Expenses = ₹15,000

Savings  = ₹60,000

Savings Rate = (60000 / 75000) × 100

Savings Rate = 80%
```

**Important:** When income is zero, savings rate is undefined. We will return `null` instead of dividing by zero.

Also, net balance here is a period-based cash-flow calculation. It is not necessarily the user's actual bank balance because opening balances, transfers, liabilities, and other accounts are outside our current project scope.

## 6.5 Get Recent Transactions

We want to retrieve the latest expenses and incomes together.

```javascript
async function getRecentTransactions(userId, limit = 10) {

    const [expenses, incomes] = await Promise.all([

        Expense.findAll({

            where: { userId },

            attributes: [

                "id",

                "amount",

                "description",

                ["expenseDate", "transactionDate"]

            ],

            include: [

                {
                    model: Category,

                    as: "category",

                    attributes: ["name"]

                }

            ],

            order: [["expenseDate", "DESC"]],

            limit

        }),

        Income.findAll({

            where: { userId },

            attributes: [

                "id",

                "amount",

                "description",

                ["incomeDate", "transactionDate"]

            ],

            include: [

                {
                    model: Category,

                    as: "category",

                    attributes: ["name"]

                }

            ],

            order: [["incomeDate", "DESC"]],

            limit

        })

    ]);


    const transactions = [

        ...expenses.map(item => ({

            id: String(item.id),

            type: "expense",

            amount: item.amount,

            description: item.description,

            date: item.get("transactionDate"),

            category: item.category?.name ?? null

        })),

        ...incomes.map(item => ({

            id: String(item.id),

            type: "income",

            amount: item.amount,

            description: item.description,

            date: item.get("transactionDate"),

            category: item.category?.name ?? null

        }))

    ];


    return transactions

        .sort((a, b) =>

            String(b.date).localeCompare(String(a.date))

        )

        .slice(0, limit);

}
```

### Why do we use Promise.all()?

We have two independent database queries:

1. Retrieve expenses.
2. Retrieve incomes.

Instead of executing them sequentially:

```javascript
const expenses = await Expense.findAll();

const incomes = await Income.findAll();
```

We execute them concurrently:

```javascript
const [expenses, incomes] = await Promise.all([
    Expense.findAll(),
    Income.findAll()
]);
```

This can reduce total waiting time.

However, both queries still consume database resources, so concurrency should be considered when designing high-traffic systems.

### Important limitation

The example retrieves the latest records from each table and merges them in JavaScript.

For large datasets, a database-level `UNION ALL` query can be more efficient because it allows MySQL to perform the combined sorting and limiting.

Also, sorting by date alone does not establish a deterministic order when multiple transactions have the same date. A production implementation should use a stable secondary sort key.

```javascript
            dashboardRepository.getTotalExpenses(
                userId,
                startDate,
                endDate
            )

        ]);


        const totalIncome = new Decimal(income);

        const totalExpenses = new Decimal(expenses);


        const netBalance = totalIncome.minus(totalExpenses);


        const savingsRate = totalIncome.isZero()

            ? null

            : netBalance
                .dividedBy(totalIncome)
                .times(100);


        return {

            period: {
                startDate,
                endDate
            },

            totalIncome: totalIncome.toFixed(2),

            totalExpenses: totalExpenses.toFixed(2),

            netBalance: netBalance.toFixed(2),

            savingsRate: savingsRate === null

                ? null

                : savingsRate.toFixed(2)

        };

    }


    async getExpenseCategories(userId, startDate, endDate) {

        const categories =
            await dashboardRepository.getExpenseCategoryTotals(
                userId,
                startDate,
                endDate
            );


        return categories.map(item => ({

            category: item.category?.name ?? "Uncategorized",

            categoryId: item.categoryId,

            totalAmount: new Decimal(item.get("totalAmount"))
                .toFixed(2)

        }));

    }


    async getIncomeCategories(userId, startDate, endDate) {

        const categories =
            await dashboardRepository.getIncomeCategoryTotals(
                userId,
                startDate,
                endDate
            );


        return categories.map(item => ({

            category: item.category?.name ?? "Uncategorized",

            categoryId: item.categoryId,

            totalAmount: new Decimal(item.get("totalAmount"))
                .toFixed(2)

        }));

    }


    async getRecentTransactions(userId, limit) {

        return await dashboardRepository.getRecentTransactions(
            userId,
            limit
        );

    }


    async getTopExpenses(userId, startDate, endDate, limit) {

        const expenses =
            await dashboardRepository.getTopExpenses(
                userId,
                startDate,
                endDate,
                limit
            );


        return expenses.map(item => ({

            id: String(item.id),

            amount: item.amount,

            description: item.description,

            date: item.expenseDate,

            category: item.category?.name ?? "Uncategorized"

        }));

    }

}


module.exports = new DashboardService();
```

### Understanding the savings rate calculation

We use:

```javascript
netBalance.dividedBy(totalIncome).times(100);
```

Why not:

```javascript
(netBalance / totalIncome) * 100;
```

Because `decimal.js` performs decimal arithmetic without relying on JavaScript's binary floating-point calculations.

# 11. Monthly Summary Service

We also need to combine monthly income and expense totals.

Add the following method to `DashboardService`:

```javascript
async getMonthlySummary(userId, year, months) {

    const endDate = `${year}-12-31`;

    const startYear = year - Math.floor((months - 1) / 12);

    const startMonth = ((months - 1) % 12) + 1;

    const startDate =
        `${startYear}-${String(startMonth).padStart(2, "0")}-01`;


    const [
        incomeRecords,
        expenseRecords
    ] = await Promise.all([

        dashboardRepository.getMonthlyIncomeTotals(
            userId,
            startDate,
            endDate
        ),

        dashboardRepository.getMonthlyExpenseTotals(
            userId,
            startDate,
            endDate
        )

    ]);


    const incomeMap = new Map(

        incomeRecords.map(item => [
            item.month,
            item.totalAmount
        ])

    );


    const expenseMap = new Map(

        expenseRecords.map(item => [
            item.month,
            item.totalAmount
        ])

    );


    const results = [];


    const cursor = new Date(
        `${startDate}T00:00:00.000Z`
    );

    const end = new Date(
        `${endDate}T00:00:00.000Z`
    );


    while (cursor <= end) {

        const month = cursor.toISOString().slice(0, 7);


        const income = new Decimal(
            incomeMap.get(month) || "0"
        );


        const expenses = new Decimal(
            expenseMap.get(month) || "0"
        );


        results.push({

            month,

            income: income.toFixed(2),

            expenses: expenses.toFixed(2),

            balance: income.minus(expenses).toFixed(2)

        });


        cursor.setUTCMonth(cursor.getUTCMonth() + 1);

    }


    return results;

}
```

Add it inside the `DashboardService` class.

### Why do we use Maps?

Consider:

```javascript
const incomeMap = new Map([
    ["2026-01", "50000.00"],
    ["2026-02", "55000.00"]
]);
```

We can retrieve values using:

```javascript
incomeMap.get("2026-01");
```

Maps provide efficient key-based lookups.

We use the month as the key so that income and expenses can be combined easily.

### Why generate missing months?

Suppose the user has transactions in January and March but none in February.

Database results might contain:

```json
[
    {
        "month": "2026-01",
        "totalAmount": "50000.00"
    },
    {
        "month": "2026-03",
        "totalAmount": "60000.00"
    }
]
```

But the frontend chart should display February too:

```json
[
    {
        "month": "2026-01",
        "income": "50000.00",
        "expenses": "20000.00"
    },
    {
        "month": "2026-02",
        "income": "0.00",
        "expenses": "0.00"
    },
    {
        "month": "2026-03",
        "income": "60000.00",
        "expenses": "25000.00"
    }
]
```

That is why we generate the complete month sequence and fill missing values with zero.

# 17. Understanding WHERE vs HAVING

These two SQL clauses are important when working with analytics.

### WHERE

Filters individual records before grouping.

Example:

```sql
SELECT
    category_id,
    SUM(amount) AS total
FROM expenses
WHERE user_id = 10
GROUP BY category_id;
```

Here, we first select expenses belonging to User 10 and then group them by category.

### HAVING

Filters groups after aggregation.

Example:

```sql
SELECT
    category_id,
    SUM(amount) AS total
FROM expenses
WHERE user_id = 10
GROUP BY category_id
HAVING SUM(amount) > 5000;
```

This returns only categories where the total expenses exceed ₹5,000.

### Difference

| WHERE | HAVING |
|---|---|
| Filters rows | Filters groups |
| Applied before GROUP BY | Applied after GROUP BY |
| Commonly filters normal columns | Commonly filters aggregate results |

# 18. Dashboard Performance Optimization

Dashboard APIs can become expensive because they execute multiple aggregate queries.

As the application grows, we need to optimize them.

## 18.1 Add Database Indexes

Consider these indexes:

```sql
CREATE INDEX idx_expenses_user_date
ON expenses(user_id, expense_date);

CREATE INDEX idx_expenses_user_category
ON expenses(user_id, category_id);

CREATE INDEX idx_incomes_user_date
ON incomes(user_id, income_date);

CREATE INDEX idx_incomes_user_category
ON incomes(user_id, category_id);
```

These can improve queries that filter by user and date or category.

Always check query plans with:

```sql
EXPLAIN
SELECT SUM(amount)
FROM expenses
WHERE user_id = 10
AND expense_date BETWEEN '2026-11-01' AND '2026-11-30';
```

## 18.2 Avoid Fetching Unnecessary Columns

Avoid:

```javascript
await Expense.findAll();
```

When you only need the amount.

Prefer:

```javascript
await Expense.findAll({
    attributes: ["amount"]
});
```

Even better, use an aggregate query:

```javascript
await Expense.sum("amount", {
    where: {
        userId
    }
});
```

## 18.3 Use Caching

Suppose a user opens the dashboard repeatedly.

The application may execute the same aggregate queries each time.

We can cache dashboard summaries using Redis.

Example:

```text
dashboard:summary:user:10:2026-11
```

The cache might expire after 60 seconds.

When the user creates or updates an expense, we can invalidate or refresh the relevant cache.

We will implement Redis caching in a later part.

## 18.4 Use Background Aggregation for Large Datasets

For a small application, calculating totals directly from the transaction tables is usually sufficient.

For very large datasets, we can maintain summary tables such as:

```text
monthly_financial_summaries
```

Example:

| User ID | Month | Income | Expenses |
|---:|---|---:|---:|
| 10 | 2026-10 | 70,000 | 25,000 |
| 10 | 2026-11 | 75,000 | 15,000 |

This reduces the need to repeatedly aggregate thousands or millions of transaction records.

However, summary tables introduce consistency challenges. Updates, deletions, and corrections must also update the corresponding summaries.

# 19. Important Production Considerations

Our implementation is an educational foundation. Before production, address these points:

| Area | Consideration |
|---|---|
| Financial arithmetic | Use `decimal.js` or another decimal-safe library |
| Date filtering | Use consistent date and timezone policies |
| Authentication | Restrict every query to the authenticated user |
| Missing periods | Fill missing days/months with zero |
| Recent transactions | Use stable ordering and database-level limiting |
| Aggregate queries | Verify generated SQL and query plans |
| Performance | Add indexes based on real query patterns |
| Caching | Use Redis when repeated calculations become expensive |
| Savings rate | Handle zero income |
| Reporting | Define whether reports use transaction date or creation date |

### Important date-handling detail

Our current `expenses` and `incomes` models use `DATE` columns.

A date such as:

```text
2026-11-24
```

does not contain a time component.

If your application later changes these fields to `DATETIME` or `TIMESTAMP`, date-range filtering needs more careful timezone handling.

For example, filtering a timestamp using:

```sql
created_at <= '2026-11-30'
```

may exclude records later on November 30.

A safer timestamp range is:

```sql
created_at >= '2026-11-01 00:00:00'
AND created_at < '2026-12-01 00:00:00'
```

This uses an exclusive upper boundary.

# 20. Interview Questions and Answers

### Q1. What is a dashboard API?

An API that provides summarized and aggregated application data for dashboard interfaces.

### Q2. What are SQL aggregate functions?

Functions such as SUM, COUNT, AVG, MIN, and MAX that calculate summary values from multiple records.

### Q3. What is GROUP BY?

It groups records sharing the same values so aggregate functions can calculate results for each group.

### Q4. What is the difference between WHERE and HAVING?

WHERE filters records before grouping, while HAVING filters grouped results after aggregation.

### Q5. What is the purpose of SUM()?

It calculates the total of a numeric column.

### Q6. What is a financial summary?

A collection of calculated financial metrics such as income, expenses, balance, and savings rate.

### Q7. How do you calculate net balance?

Subtract total expenses from total income.

### Q8. How do you calculate savings rate?

Divide net savings by total income and multiply by 100, provided income is nonzero.

### Q9. Why should financial calculations use decimal arithmetic?

Because ordinary JavaScript floating-point arithmetic can introduce precision errors.

### Q10. What is Promise.all()?

It executes multiple promises concurrently and resolves when all of them complete successfully.

### Q11. What is eager loading?

Retrieving associated model records as part of a Sequelize query using `include`.

### Q12. What is database indexing?

A technique that helps databases locate records more efficiently.

### Q13. What is caching?

Storing frequently requested data temporarily so it can be retrieved without repeating expensive calculations.

### Q14. What is Redis?

An in-memory data store commonly used for caching, session storage, and other low-latency data operations.

### Q15. What is a materialized summary table?

A table containing precomputed aggregate results that can be queried without recalculating everything from the original records.

### Q16. Why should dashboard APIs not retrieve every transaction?

Because retrieving unnecessary records increases database load, network usage, and application memory consumption.

### Q17. What is DATE_FORMAT() in MySQL?

A function that formats date values into a specified string representation.

### Q18. What is the purpose of a date-range filter?

It restricts financial calculations to transactions occurring within a selected period.

### Q19. Why should the backend calculate financial summaries?

It centralizes business logic, improves consistency, and avoids duplicating financial calculations across frontend clients.

### Q20. What is query optimization?

The process of improving database queries to reduce execution time and resource consumption.
